## How to reproduce the results

1. Set up the environment from the repository root (see the main `README.md`). **Python ≥ 3.10 is required**
   (the pinned `numpy==2.2.6` does not install on 3.8/3.9). We used Python 3.11.
   ```bash
   python3.11 -m venv irwa_venv
   source irwa_venv/bin/activate
   pip install -r requirements.txt
   ```
2. Put the two data files provided in Aula Global in the `data/` folder (they are not committed, see `.gitignore`):
   ```
   data/fashion_products_dataset.json
   data/validation_labels.csv
   ```
3. Run the notebook from this folder (it finds the repository root by itself):
   ```bash
   cd project_progress/part_1
   jupyter notebook IRWA_part_1.ipynb        # interactive
   # or, non-interactive (re-executes every cell, ~6 min, NER is the slow part):
   jupyter nbconvert --to notebook --execute --inplace IRWA_part_1.ipynb
   ```
   NLTK resources (`stopwords`, `punkt`) are downloaded automatically by the first cell.

Running the notebook also writes `data/processed_corpus.pkl` (the pre-processed corpus that will be the
input of Part 2) and regenerates everything in `figures/`.

## Using the pre-processing from your own code

```python
import preprocessing as pp

pp.preprocess_text("Women's Full-Sleeve Sweatshirt")   # ['women', 'full', 'sleev', 'sweatshirt']
pp.preprocess_text("Printed shirts", stem=False)       # options: stem, remove_stopwords, remove_codes

import pandas as pd
corpus = pp.preprocess_corpus(pd.read_json("data/fashion_products_dataset.json"))
corpus.loc["TKPFCZ9EA7H5FYZH", ["title_terms", "product_details_terms", "all_terms"]]
```

Main functions:

| Function | Purpose |
|---|---|
| `preprocess_text(text, stem=True, remove_stopwords=True, remove_codes=True)` | full text pipeline (documents and queries) |
| `preprocess_document(raw)` / `preprocess_corpus(df)` | one record / whole corpus → clean output fields + term lists per field + `all_terms` |
| `flatten_product_details(details)` | product details → text (values only, non-descriptive keys removed) |
| `brand_from_url(brand, url)` | completes truncated brands (`"Pu"` → `"puma"`) using the URL slug |
| `parse_price`, `parse_discount`, `parse_rating` | `"2,999"` → `2999.0`, `"69% off"` → `69.0`, missing → `None` |

## Summary of the decisions

- **Text pipeline:** encoding repair → ASCII folding → split glued words → lowercase → domain normalisation
  (`women's` → `women`, `t-shirt` → `tshirt`, …) → regex tokenization (removes punctuation) → NLTK stop words →
  remove product codes and 1-char tokens → Porter stemming.
- **Categorical fields (Q3):** one term list per field (title, description, product_details, brand,
  sub_category, category, seller), plus a merged `all_terms` field (title + description + brand + sub_category +
  product_details), plus the raw values for filtering. `category` and `seller` are not in the merged field.
- **Numeric fields (Q4):** parsed into numbers/booleans and not indexed as text; they will be used as filters
  and ranking signals. Missing values stay missing (never 0).
- **URL:** not indexed as text (its gender words contradict the title in ~50% of the products), only used to complete brand names.

The justification of each decision is in the notebook and in the report.
