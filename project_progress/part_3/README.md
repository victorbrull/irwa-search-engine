## How to reproduce the results

1. Set up the environment as in Parts 1 and 2 (see the main `README.md`; Python ≥ 3.10, we used 3.13). Part 3 needs one new
   package, **gensim** (it also installs scipy), which is already in `requirements.txt`:
   ```bash
   pip install -r requirements.txt
   ```
2. The data files go in `data/` (they are not committed, see `.gitignore`):
   ```
   data/fashion_products_dataset.json
   data/validation_labels.csv
   ```
3. Run the notebook from this folder. It uses `data/processed_corpus.pkl` (written by the Part 1 notebook) and, if the file is
   missing, it creates it with the Part 1 pre-processing (~40 s). **Nothing of `project_progress/part_1` or `part_2` is modified.**
   ```bash
   cd project_progress/part_3
   jupyter notebook ranking_filtering.ipynb          # interactive
   # or, non-interactive (~3 min; the skip-gram and doc2vec models of section 6 are the slow part):
   jupyter nbconvert --to notebook --execute --inplace ranking_filtering.ipynb
   ```
4. Tests (they are also run inside the notebook):
   ```bash
   python test_part3.py        # or: python -m pytest test_part3.py
   ```

Running the notebook rewrites `results/` and `figures/`.

**Word vectors.** The notebook and `search.py` read `models/word2vec_fashion.bin`. If the file is deleted, the vectors are
trained again (about 1 minute, one thread, fixed seed) and saved in the same place. On our machine the training gives exactly
the same file; on another machine or with another version of gensim / NumPy the vectors can differ slightly, which is why the
file is committed. The skip-gram and doc2vec models of section 6 are always trained by the notebook and are not stored, so their
figures can change in the third decimal on another machine.

## Selecting the ranking method

### From the command line

```bash
cd project_progress/part_3
python search.py "men denim jacket"                           # TF-IDF + cosine (default), top 20
python search.py "men denim jacket" --method bm25 --top 10    # BM25
python search.py "men denim jacket" --method custom           # our score
python search.py "men denim jacket" --method word2vec         # word2vec + cosine
python search.py "men denim jacket" --method all --top 5      # the four rankings, one after the other
```

| Option | Meaning | Default |
|---|---|---|
| `--method` | `tfidf`, `bm25`, `custom`, `word2vec` or `all` | `tfidf` |
| `--top` | number of results shown | 20 |
| `--k1`, `--b` | BM25 parameters (also used by the BM25 part of our score) | 1.2, 0.75 |
| `--title-boost` | our score: weight λ of the query terms found in the title | 1.0 |
| `--rating-weight` | our score: weight α of the average rating | 0.5 |
| `--discount-weight` | our score: weight β of the discount | 0.25 |
| `--out-of-stock-factor` | our score: factor γ applied to the products that are out of stock | 0.5 |

Every method uses conjunctive (AND) semantics: only the documents that contain all the query terms are returned, and the
method only decides their order. `python search.py -h` shows the same help.

### From your own code

```python
import sys; sys.path.insert(0, "project_progress/part_3")    # or run from this folder
import pandas as pd
import ranking as rk                # also makes the Part 1 and Part 2 modules importable
import preprocessing as pp          # Part 1, unchanged

corpus = pd.read_pickle("data/processed_corpus.pkl")
engines = rk.build_engines(corpus, pp.preprocess_text, "project_progress/part_3/models/word2vec_fashion.bin")

engines["tfidf"].search("men denim jacket", top_k=20)        # [(pid, score), ...]
engines["bm25"].search("men denim jacket", top_k=20)
engines["custom"].search("men denim jacket", top_k=20)
engines["word2vec"].search("men denim jacket", top_k=20)

# other parameters
engines = rk.build_engines(corpus, pp.preprocess_text, methods=("bm25", "custom"), bm25_b=1.0,
                           custom_params=rk.CustomScoreParams(rating_weight=1.0, out_of_stock_factor=0.25))
```

Main classes and functions of `ranking.py`:

| Name | Purpose |
|---|---|
| `build_engines(corpus, preprocess, word2vec_path, ...)` | one `SearchEngine` (Part 2) per method: `tfidf`, `bm25`, `custom`, `word2vec` |
| `CustomRanker`, `CustomScoreParams` | our score and its weights; `components(query_terms, doc_id)` returns every factor of the score of a document |
| `train_word2vec`, `load_or_train_word2vec` | training of the word vectors on the collection / loading of the stored file |
| `text_vector(wv, terms)` | vector of a text = average of the vectors of its words |
| `Word2VecRanker` | cosine between the query vector and the document vectors (options for the weighted averages of section 6) |
| `train_doc2vec`, `Doc2VecRanker` | doc2vec (PV-DBOW / PV-DM) with an inferred query vector, only for the comparison of section 6 |

## Summary of the decisions

- **Pipeline:** query → `preprocess_text` (Part 1) → conjunctive retrieval on the inverted index of Part 2 → ranking. The four
  methods return the same documents; only the order changes.
- **TF-IDF + cosine and BM25:** the implementations of Part 2 (`TfidfRanker`, `Bm25Ranker`, k1 = 1.2, b = 0.75), not copied.
- **Our score:** `BM25 · (1 + λ·title) · (1 + α·rating + β·discount) · stock`. The text part decides, the numeric fields rescale
  it inside a bounded range. Missing rating → mean of the collection; missing discount → 0; price is not used.
- **word2vec:** trained on the pre-processed terms of our collection (CBOW, 100 dimensions, window 5, `min_count` 1, 30 epochs),
  because the index terms are stems and brand names that are not in pre-trained vocabularies. A text is the average of the
  vectors of all its words; documents use the indexed field `all_terms`.
- **Evaluation:** the seven queries and the judgments of Part 2 with the same protocol (condensed list for the two validation
  queries, whole ranking for our five queries), plus the rating, discount and stock of the products in the first positions.
- **Better representations:** IDF-weighted average, SIF, title-only average and doc2vec are compared with the same pipeline;
  sentence encoders based on transformers are discussed in the report but not tested.

The justification of each decision is in the notebook and in the report.

**Note.** The TF-IDF figures of this part (MAP 0.764 / 0.737) are slightly different from the ones in the Part 2 report
(0.760 / 0.723): those were computed with base-10 logarithms in the TF-IDF weights and `../part_2/indexing.py` now uses base 2.
